# Unirack-1 — спецификация протокола MQTT

Документ описывает фактическое поведение прошивки Unirack-1 (файл `main.py`).
Версия протокола соответствует прошивке от 2026-07-10.

---

## 1. Общие сведения

| Параметр | Значение |
|----------|----------|
| Роль устройства | MQTT-клиент (брокер — отдельный узел сети) |
| Версия протокола | MQTT 3.1.1 (protocol level 4) |
| Client ID | `unirack1-relay-01` |
| Сессия | Clean Session = 1 (подписки восстанавливаются при каждом подключении) |
| Аутентификация | нет (username/password не используются) |
| Шифрование | нет (TLS не поддерживается) |
| Порт брокера | настраивается, по умолчанию `1883` |
| Keep-Alive | 30 секунд |
| QoS исходящих | 0 (без подтверждений) |
| QoS подписок | 0; входящие QoS 1 подтверждаются PUBACK, QoS 2 не поддерживается |
| Base topic | настраивается в вебке, по умолчанию `unirack1` |

Во всех топиках ниже `<base>` — значение поля **Base Topic** из веб-интерфейса.

### 1.1. Жизненный цикл соединения

- При включённом MQTT плата пытается подключиться к брокеру каждые **2.5 с**.
- После успешного подключения плата:
  1. подписывается на `<base>/relay/+/set`, `<base>/relay/all/set`, `<base>/system/get`;
  2. публикует `system/online`, состояния всех реле, показания датчиков,
     полный снимок `system/state` и `system/heartbeat`.
- PINGREQ отправляется, если исходящих пакетов не было более 15 с.
- Если от брокера нет входящих пакетов более **60 с** — соединение считается
  потерянным, сокет закрывается, начинаются переподключения.
- При потере Ethernet-линка соединение закрывается немедленно.

### 1.2. Обнаружение офлайна устройства

⚠️ **Last Will (LWT) не используется.** Топик `system/online` retained и
**не сбрасывается** при обрыве связи — по нему нельзя судить, что плата жива.

Признак живого устройства — **`system/heartbeat` приходит каждые 15 с**.
Рекомендация для интеграций: считать устройство офлайн, если heartbeat
отсутствует более 45 секунд (3 пропущенных интервала).

## 2. Топики, публикуемые платой

| Топик | Payload | Retain | Когда публикуется |
|-------|---------|--------|-------------------|
| `<base>/relay/<n>/state` | `ON` \| `OFF` | да | при изменении реле, при подключении |
| `<base>/sensor/temperature` | число, °C, 1 знак (напр. `23.4`) | да | DHT22: изменение ≥ 0.1, опрос раз в 30 с |
| `<base>/sensor/humidity` | число, %, 1 знак (напр. `41.9`) | да | DHT22: изменение ≥ 0.1 |
| `<base>/sensor2/temperature` | число, °C, 1 знак | да | первый DS18B20: изменение ≥ 0.1, опрос раз в 3 с |
| `<base>/door/state` | `OPEN` \| `CLOSED` | да | Дверь 1 (DI7): при изменении |
| `<base>/door2/state` | `OPEN` \| `CLOSED` | да | Дверь 2 (DI8): при изменении |
| `<base>/system/online` | `online` | да | один раз при подключении (LWT нет — см. 1.2) |
| `<base>/system/heartbeat` | JSON (см. 4.1) | **нет** | каждые 15 с |
| `<base>/system/state` | JSON (см. 4.2) | да | при любом изменении состояния и при подключении |
| `<base>/test` | `ping:<uptime_ms>` | нет | по кнопке Test MQTT в вебке |

`<n>` — номер реле 1..8 (назначение — см. раздел 5).

**Семантика реле логическая**: `ON` = нагрузка запитана. Реле 1–7 коммутируют
через нормально-замкнутые контакты, но прошивка это учитывает — подписчику
думать об этом не нужно.

**Состояние дверей**: `CLOSED` = дверь закрыта (контакт датчика замкнут),
`OPEN` = дверь открыта. Логика входа настраивается в вебке (см. 6).

## 3. Топики, на которые подписана плата (управление)

| Топик | Payload | Действие |
|-------|---------|----------|
| `<base>/relay/<n>/set` | см. 3.1 | управление реле `n` (1..8) |
| `<base>/relay/all/set` | см. 3.1 | управление всеми реле сразу |
| `<base>/system/get` | любой | плата публикует все `relay/<n>/state`, датчики, `system/state` и `system/heartbeat` |

### 3.1. Команды управления реле

Payload нечувствителен к регистру, пробелы по краям игнорируются:

| Команда | Синонимы | Действие |
|---------|----------|----------|
| `ON` | `1`, `TRUE` | включить нагрузку |
| `OFF` | `0`, `FALSE` | выключить нагрузку |
| `TOGGLE` | — | переключить реле в противоположное состояние на **5 секунд**, затем автоматически вернуть как было («передёрнуть питание») |

Любой другой payload игнорируется без ответа.

После каждого выполненного изменения плата публикует новое
`relay/<n>/state` (retained) и обновлённый `system/state`.

Некорректный номер реле (не 1..8) игнорируется.

## 4. Форматы JSON

### 4.1. `system/heartbeat`

```json
{"uptime_ms": 123456789, "ip": "192.168.1.100", "mqtt_connected": true}
```

| Поле | Тип | Описание |
|------|-----|----------|
| `uptime_ms` | int | миллисекунды с запуска платы (внутренний счётчик тиков, периодически переполняется) |
| `ip` | string | текущий IP платы |
| `mqtt_connected` | bool | всегда `true` (публикуется только при активном соединении) |

### 4.2. `system/state` (полный снимок, retained)

```json
{
  "relays": [1, 1, 1, 1, 1, 1, 1, 0],
  "temp_c": 23.4,
  "temp2_c": 22.8,
  "ds18_temps": [22.8, 23.6],
  "ds18_count": 2,
  "hum_pct": 41.9,
  "door_closed": 1,
  "door2_closed": 0,
  "di": [0, 0, 0, 0, 1, 0],
  "di_pull_modes": [1, 1, 1, 1, 1, 1],
  "pz": {"v": 230.5, "a": 1.234, "w": 284.6},
  "mqtt_enabled": true,
  "mqtt_connected": true,
  "broker_ip": "192.168.1.10",
  "broker_port": 1883,
  "base_topic": "unirack1",
  "uptime_ms": 123456789,
  "ip": "192.168.1.100"
}
```

| Поле | Тип | Описание |
|------|-----|----------|
| `relays` | int[8] | логические состояния реле 1..8: `1` = нагрузка запитана |
| `temp_c` | float\|null | температура DHT22 (THS), °C |
| `hum_pct` | float\|null | влажность DHT22 (THS), % |
| `temp2_c` | float\|null | температура первого DS18B20 (TS), °C |
| `ds18_temps` | (float\|null)[] | все найденные DS18B20, °C; `null` — ошибка чтения датчика |
| `ds18_count` | int | сколько DS18B20 обнаружено на шине |
| `door_closed` | 0\|1\|null | Дверь 1 (DI7): `1` = закрыта; `null` = ещё не опрошена |
| `door2_closed` | 0\|1\|null | Дверь 2 (DI8): `1` = закрыта |
| `di` | (0\|1\|null)[6] | активность DI3..DI8 (индекс 0 = DI3): `1` = вход активен (контакт в «активном» положении с учётом логики) |
| `di_pull_modes` | (0\|1)[6] | логика DI3..DI8: `1` = ACTIVE=CLOSED (активен при замыкании на GND), `0` = ACTIVE=OPEN (инверсия) |
| `pz` | object | измеритель PZEM: `v` — вольты, `a` — амперы, `w` — ватты; `null` — нет данных |
| `mqtt_enabled` | bool | включён ли MQTT в настройках |
| `mqtt_connected` | bool | состояние соединения |
| `broker_ip`, `broker_port`, `base_topic` | — | текущие настройки MQTT |
| `uptime_ms`, `ip` | — | как в heartbeat |

Датчики без подключения дают `null` (JSON) — интеграция должна это учитывать.

Примечание: `door_closed` дублирует `di[4]` (DI7), `door2_closed` — `di[5]` (DI8).

## 5. Назначение реле

| n | Название | Английское имя | После подачи питания |
|---|----------|----------------|----------------------|
| 1 | Розетка 1 | PowerOutlet1 | `ON` |
| 2 | Розетка 2 | PowerOutlet2 | `ON` |
| 3 | Розетка 3 | PowerOutlet3 | `ON` |
| 4 | Розетка 4 | PowerOutlet4 | `ON` |
| 5 | Блок питания 1 | PowerSupply1 | `ON` |
| 6 | Блок питания 2 | PowerSupply2 | `ON` |
| 7 | Вентиляторы | FAN | `ON` |
| 8 | Выход на контактор | ToContactor | `OFF` |

⚠️ Состояния реле **не сохраняются** при перезагрузке/сбое питания: плата
всегда стартует в состоянии из таблицы. Retained-сообщения `relay/<n>/state`
обновятся при первом подключении к брокеру.

## 5.1. Назначение цифровых входов (для поля `di`)

| Индекс в `di` | Вход | Название |
|---------------|------|----------|
| 0 | DI3 | Цифровой вход 1 (DigitalInput1) |
| 1 | DI4 | Цифровой вход 2 (DigitalInput2) |
| 2 | DI5 | Цифровой вход 3 (DigitalInput3) |
| 3 | DI6 | Сброс настроек (Reset) — зарезервирован, логика всегда прямая |
| 4 | DI7 | Дверь 1 (Door1) |
| 5 | DI8 | Дверь 2 (Door2) |

## 6. Настройка

Все параметры MQTT задаются в веб-интерфейсе платы (блок **MQTT Settings**):
Enable MQTT, Broker IP, Broker Port, Base Topic. Логика входов DI3..DI8 —
кнопки `ACTIVE=CLOSED` / `ACTIVE=OPEN` там же. Настройки сохраняются в файле
`mqtt_config.json` на плате и переживают перезагрузку.

Смена настроек MQTT сразу разрывает текущее соединение и переподключает
с новыми параметрами.

## 7. Примеры

### 7.1. mosquitto (командная строка)

```bash
# наблюдать всё от устройства
mosquitto_sub -h 192.168.1.10 -t 'unirack1/#' -v

# выключить Розетку 2
mosquitto_pub -h 192.168.1.10 -t unirack1/relay/2/set -m OFF

# передёрнуть питание Розетки 2 (выкл на 5 с, потом снова вкл)
mosquitto_pub -h 192.168.1.10 -t unirack1/relay/2/set -m TOGGLE

# включить контактор
mosquitto_pub -h 192.168.1.10 -t unirack1/relay/8/set -m ON

# всё выключить
mosquitto_pub -h 192.168.1.10 -t unirack1/relay/all/set -m OFF

# запросить полное состояние
mosquitto_pub -h 192.168.1.10 -t unirack1/system/get -m 1

# следить за дверями
mosquitto_sub -h 192.168.1.10 -t 'unirack1/door/state' -t 'unirack1/door2/state' -v
```

### 7.2. Home Assistant (configuration.yaml)

```yaml
mqtt:
  switch:
    - name: "Unirack Розетка 1"
      command_topic: "unirack1/relay/1/set"
      state_topic: "unirack1/relay/1/state"
      payload_on: "ON"
      payload_off: "OFF"

  binary_sensor:
    - name: "Unirack Дверь 1"
      state_topic: "unirack1/door/state"
      payload_on: "OPEN"       # включён = дверь открыта
      payload_off: "CLOSED"
      device_class: door

  sensor:
    - name: "Unirack Температура"
      state_topic: "unirack1/sensor/temperature"
      unit_of_measurement: "°C"
      device_class: temperature
    - name: "Unirack Влажность"
      state_topic: "unirack1/sensor/humidity"
      unit_of_measurement: "%"
      device_class: humidity
    - name: "Unirack Мощность"
      state_topic: "unirack1/system/state"
      value_template: "{{ value_json.pz.w }}"
      unit_of_measurement: "W"
      device_class: power
```

Доступность устройства в HA удобно строить на heartbeat через
`expire_after` у отдельного sensor или автоматизацию-сторож.

### 7.3. Python (paho-mqtt)

```python
import json
import paho.mqtt.client as mqtt

BASE = "unirack1"

def on_connect(client, userdata, flags, rc):
    client.subscribe(f"{BASE}/system/state")
    client.publish(f"{BASE}/system/get", "1")   # запросить снимок

def on_message(client, userdata, msg):
    state = json.loads(msg.payload)
    print("Реле:", state["relays"], "| Дверь 1 закрыта:", state["door_closed"])

c = mqtt.Client()
c.on_connect = on_connect
c.on_message = on_message
c.connect("192.168.1.10", 1883)
c.publish(f"{BASE}/relay/7/set", "OFF")         # выключить вентиляторы
c.loop_forever()
```

## 8. Ограничения и особенности

- **Один брокер** — адрес задаётся вручную, авто-обнаружения нет.
- **Нет LWT** — офлайн определять по отсутствию heartbeat (см. 1.2).
- **QoS 0** на публикациях: при нестабильной сети отдельное сообщение может
  потеряться; актуальное состояние всегда можно получить через `system/get`
  или из retained `system/state`.
- **Состояния реле не энергонезависимы** — после сбоя питания реле 1–7 `ON`,
  реле 8 `OFF` (см. раздел 5).
- `uptime_ms` — внутренний счётчик тиков MicroPython, переполняется примерно
  каждые 12 суток; для мониторинга аптайма используйте факт приёма heartbeat,
  а не абсолютное значение.
- Несколько устройств Unirack-1 на одном брокере: задайте каждому **свой
  Base Topic** (`unirack1`, `unirack2`, …). Client ID у всех одинаковый —
  два устройства с одинаковым base topic и одним брокером работать не будут
  (брокер будет разрывать сессии).
