Требования заказчика к прошивке Unirack-1 (переданы списком 10.07.2026, нумерация — по этому списку) и то, что добавилось после отгрузки. Актуальная прошивка — `MQTT-2-0/main.py` в репозитории.

| Номер | Требование | Описание | Урок | Статус |
|---|---|---|---|---|
| 1.1 | Убрать название Waveshare, везде Unirack-1 | Веб-интерфейс, заголовки, MQTT base topic `unirack1`, client id | В MQTT-топиках дефис не используем — базовый топик `unirack1` | ✅ Готово |
| 1.2 | Переименовать реле и исправить логику кнопок | Реле 1–4 = Розетка 1–4 (PowerOutlet), 5–6 = Блок питания (PowerSupply), 7 = Вентиляторы (FAN), 8 = Выход на контактор (ToContactor) | Реле 1–7 коммутируют через **НЗ-контакты**: после подачи питания нагрузка запитана при GPIO=0. Вместо переименования кнопок ввели логическое состояние (`relay_logical`): ON везде = «нагрузка запитана», прошивка сама учитывает инверсию. Реле 8 — НО, обычная логика | ✅ Готово |
| 1.3 | Переименовать DI, двери на реальные входы | DI1/DI2 не выведены — убраны из кода (GPIO9/10). DI3–DI5 = Цифровой вход 1–3, DI6 = Сброс настроек (Reset), DI7/DI8 = Дверь 1/2 | Дверные датчики **замыкают контакт при закрытии** — прямая логика (`ACTIVE=CLOSED`). Первая проверка на объекте дала ложный вывод об инверсии, сделали и откатили; в вебке остались кнопки `ACTIVE=CLOSED/OPEN` на случай других датчиков. Фикс: переключение логики больше не меняет подтяжку пина (иначе сухой контакт на GND переставал читаться) | ✅ Готово |
| 1.4 | Назвать клеммы датчиков | EnergyMonitor: `EM TX/RX/+5/GND` (PZEM-004T, опция); TemperatureSensor: `TS Data/VDD/GND` (DS18B20 ×3 в комплекте, параллельно + резистор 4.7 кОм); TempHumSensor: `THS Data/VDD/GND` (DHT22 ×1 в комплекте) | | ✅ Готово |
| 2 | Выборочно проверить | Проверено на ПК (local_preview.py гоняет настоящий код вебки без платы) и на живых платах по HTTP: стартовые состояния реле, управление, DI, страница | `local_preview.py` подменяет железные модули заглушками и исполняет настоящий `main.py` — превью всегда синхронно с прошивкой | ✅ Готово |
| 3 | Инструкция и листик с контактами | `ИНСТРУКЦИЯ.md`, `КОНТАКТЫ.md`, `CHECKLIST.md`, `README_MQTT.md`, `ПРОТОКОЛ_MQTT.md` + PDF-версии всех (генерация: markdown → HTML → headless Chrome) | Для кириллицы в PDF хватает headless Chrome — pandoc/LaTeX не нужны | ✅ Готово |
| 4 | Прошить партию 12 устройств | Все 12 прошиты 10.07.2026 скриптом `flash_unirack.ps1` (автопоиск платы, повторы, сверка размеров, сброс конфига, reset) | mpremote падает «could not enter raw repl», если плата ещё грузится — нужны повторы. `.ps1` с кириллицей обязан быть в UTF-8 **с BOM**, иначе PowerShell 5.1 ломается на парсинге (байт `Г` = кавычка в cp1251) | ✅ Готово |
| 5 | Уникальный MAC-адрес (рекламация 18.09.2026) | У всех устройств MAC был зашит константой `00:08:DC:12:34:56` — два устройства в одной сети не работали. Теперь MAC = `02:08:DC` + 3 байта `machine.unique_id()`, заодно уникальный MQTT Client ID; MAC виден в вебке и `/api/state`. Коммит `9aca0d6`, пакет обновления для заказчика `Unirack-1-update-MAC.zip` (настройки устройства сохраняет) | **Не зашивать идентификаторы константами** — всё, что должно отличаться между устройствами (MAC, client id), генерировать из `machine.unique_id()`. Обновление в поле — только по USB, OTA нет | ⚠️ Частично — прошивка готова, устройства у заказчика ещё не обновлены |
| 6 | MQTT LWT | `system/online` retained и не сбрасывается при обрыве — offline определяется только по heartbeat (15 с). Нужен Last Will в следующей ревизии | | ⬜ Не начато |
